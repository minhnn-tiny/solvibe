### Chen2026-SolAgent SolAgent: A Specialized Multi-Agent Framework for Solidity Code Generation
- Authors: Wei Chen et al.; Year: 2026; Venue: arXiv preprint (arXiv:2601.23009)
- URL opened: https://arxiv.org/abs/2601.23009 (arXiv abstract page); https://arxiv.org/html/2601.23009 (arXiv HTML full text)
- Status: VERIFIED
- Tier: A
- Touches: N1, N4
- Closeness: (a) Yes. It runs Slither on "the original, human-written code in the repository" (the "Baseline Repo") and on the agent's code for the same files. (b) Count of Slither findings (High, Medium and Low together). Forge tests check function. No exploit, no Mythril, no LLM judge. (c) Real repositories, taken over from SolEval. No commit history and no audit findings.
- Summary: SolAgent is a multi-agent framework that writes Solidity files. An inner loop runs the Forge compiler and tests, and an outer loop runs Slither. On SolEval+ (81 files built from 1,125 SolEval functions, with 1,188 Foundry tests written and reviewed by the authors), it reaches up to 64.39% Pass@1, against about 25% for plain LLMs. It also beats GitHub Copilot, DeepCode, MetaGPT and Qwen-Agent. On 73 files it cuts Slither findings against the human-written code from 259 to 156 (−39.77%, GPT-5-Mini). The cut is 293 to 247 (−15.70%) with Claude Sonnet 4.5, and 242 to 182 (−24.79%) with GPT-5.1. The same test suite is the agent's feedback and the reported Pass@1, with no held-out split except in the distillation experiment.
- Delta: This is the only paper found that counts the security findings of agent-written Solidity against the human developer's code for the same task, so a reviewer could cite it against N1. But it counts Slither warnings over whole files, most of them Low severity. It does not ask whether the human's actual bug comes back, and no exploit judges either version. It has no vulnerability-introducing commit, no audit finding, and no split between functions the human got wrong and functions the human got right. Its function score is measured on the same tests the agent saw during refinement, so it cannot show an agent fitting the tests it can see. The project shows exactly that with held-out PoVs (N3, N4). In return, SolAgent offers what the project does not: a generation method, gas results, and a distilled open model.

- URL opened: https://aclanthology.org/2025.emnlp-main.218/ (ACL Anthology page); https://arxiv.org/html/2502.18793 (arXiv HTML full text)
- Status: VERIFIED. The arXiv version (2502.18793) is titled "SolEval: Benchmarking Large Language Models for Repository-level Solidity Code Generation".
- Tier: A
- Touches: N2 (partly), N1 (task setup only)
- Closeness: (a) Not for security. Gas is compared with the original repository function (Gas@k), but vulnerabilities are not. (b) Slither findings flagged high risk with high confidence (Vul@k), plus unit, fuzz, invariant and differential tests in Forge. - Summary: A function-level benchmark: the model gets a signature, a natural-language requirement and repository context, and writes the function. ### Storhaug2023-VCD Efficient Avoidance of Vulnerabilities in Auto-completed Smart Contract Code Using Vulnerability-constrained Decoding
- Authors: André Storhaug et al.; Year: 2023; Venue: 34th IEEE International Symposium on Software Reliability Engineering (ISSRE 2023), as stated in the arXiv comments field
- URL opened: https://arxiv.org/abs/2309.09826 (arXiv abstract page); https://arxiv.org/pdf/2309.09826 (PDF, pages 4–8 and 11 read)
- Status: VERIFIED
- Tier: A
- Touches: N1
- Closeness: (a) Partly. The model gets the code the human wrote up to the vulnerable line. The authors then check whether the completion contains the same vulnerability type. (b) Manual inspection of the completed function, limited to the type and scope of the originally labelled line. (c) Ethereum contracts with vulnerability labels from the authors' earlier dataset (Hu et al., "Why Smart Contracts Reported as Vulnerable were not Exploited?", TechRxiv 2023). No commit history and no audit findings.
- Summary: The authors fine-tuned GPT-J 6B on 186,397 deduplicated Ethereum contracts (BLEU 0.557). They cut 176 labelled vulnerable contracts just above the vulnerable line and let the model complete the function. 123 of 173 completions (71%) contained the vulnerability again. They then tuned the model to emit vulnerability labels and blocked those labels during decoding. The model labelled 58 samples correctly (62%), and decoding avoided the vulnerability in 39 of those 58 (67%).
- Delta: This is the closest Solidity counterpart to asking "does the AI repeat the human's bug from the same starting code". It differs from the project in four ways. The model is a code-completion model, not an agent working from a feature request. The bugs are pattern types (reentrancy, timestamp dependence, tx.origin, overflow and others) in older contracts, not business-logic bugs from audits. The judge is a manual type check, not an exploit. And there is no control group of functions the human wrote correctly, because every prefix comes from vulnerable code.

### Wang2026-EVMbench EVMbench: Evaluating AI Agents on Smart Contract Security
- Authors: Justin Wang et al. (OpenAI, Paradigm and OtterSec); Year: 2026; Venue: arXiv preprint (arXiv:2603.04915)
- URL opened: https://arxiv.org/html/2603.04915 (arXiv HTML full text; the first 100,000 of 122,469 characters were read)
- Status: VERIFIED
- Tier: A
- Touches: N2, N3, N4, N7 (partly)
- Closeness: (a) No. (b) Detect is scored against the audit findings. Patch is scored by the repository's existing tests plus exploit tests that are uploaded only at grading time, so the agent never sees them. Exploit is scored by the agent's wallet balance on a local chain. (c) Audit findings: 117 vulnerabilities from 40 repositories, mostly Code4rena contests from July 2023 to January 2026, plus Tempo scenarios. No vulnerability-introducing commits.
- Summary: EVMbench has three modes. Detect (117 vulnerabilities): the best score is 45.9%, by Claude Opus 4.6 in Claude Code. Patch (44 vulnerabilities): the best is 41.7%, by GPT-5.3-Codex, and GPT-5.2 reaches 90.2% with a medium hint. Exploit (23 vulnerabilities): the best is 71.0%, by GPT-5.3-Codex. In Patch mode the agent gets the repository, its tests and the README. Protected test files are reset before grading. Existing tests that "rely on vulnerable logic" may fail without penalty. Detect also reports dollar "awards", which are the historical audit payouts.
- Delta: EVMbench already grades agent patches of real audit-contest bugs with exploit tests the agent never sees, and it already admits that the repository's own tests can assert the vulnerable behaviour. So neither held-out exploit grading of Solidity repairs nor that observation is new on its own. What EVMbench does not do: it never gives the agent a PoV as a failing test; it varies hints (none, low, medium) but not what the agent can run; it does not measure repairs that block one exploit while another still works; and it has no feature-writing task and no comparison with the human developer. Its dollar figures are audit payouts, not losses per party.

### Huang2026-CyberChainBench CyberChainBench: Can AI Agents Secure Smart Contracts Against Real-World On-Chain Vulnerabilities?
- Authors: Jintao Huang et al.; Year: 2026; Venue: arXiv preprint (arXiv:2606.26216)
- URL opened: https://arxiv.org/html/2606.26216 (arXiv HTML full text)
- Status: VERIFIED
- Tier: A
- Touches: N2, N3, N7
- Closeness: (a) No. Patches are scored by behaviour, not against the official fix or the developers' code. (b) For a patch, the real attack is replayed on a historical fork and must revert or make under 1% of the original profit, and historical legitimate transactions must still succeed. For an exploit, realised profit in US dollars. (c) 541 real incidents from DeFiHackLabs on 9 EVM chains, each anchored to a block. No commits and no audit reports.
- Summary: The benchmark covers detection, exploit generation and patching. The best configuration (Codex with GPT-5.5) scores 37.5% on detection, 43.7% on exploitation and 23.4% on patching. There is no feature-writing task and no human comparison. Its profit is the attacker's total gain, not who loses how much.
