## Theme 1. Incidents: AI-written code and vibe-coded applications

### Moonwell2026-MIPX43 MIP-X43 cbETH Oracle Incident Summary
- Authors: Anthias Labs (Moonwell's risk manager), with news coverage by The Block, Cointelegraph and the OECD AI Incidents Monitor; Year: 2026; Venue: grey literature (protocol post-mortem, GitHub pull request, news reports, incident database)
- URL opened:
  - (a) https://forum.moonwell.fi/t/mip-x43-cbeth-oracle-incident-summary/2068 (forum post-mortem by user "AnthiasLabs", dated 2026-02-17; read through the forum's `.json` view of the same topic)
  - (b) https://github.com/moonwell-fi/moonwell-contracts-v2/pull/578 (pull request "Add MIP-X43: Activate OEV wrappers for all remaining markets"; commits and diffs read with the GitHub API)
  - (c) https://www.theblock.co/post/390302/defi-lending-protocol-moonwell-hit-with-1-8-million-bad-debt-after-oracle-misconfiguration (news, 18 Feb 2026, Naga Avan-Nomayo)
  - (d) https://cointelegraph.com/news/moonwell-exploit-cbeth-oracle-misprice-ai-commits-testing-audits (news, 18 Feb 2026, Christina Comben)
  - (e) https://oecd.ai/en/incidents/2026-02-18-a018 (OECD AI Incidents Monitor entry)
  - (f) https://api.llama.fi/hacks (DeFiLlama row for Moonwell, 2026-02-15)
- Status: VERIFIED (all six pages opened; the link between the bad line and a specific commit is my own reading of the diff, see Numbers)
- Tier: C
- Touches: N1, N2, N7
- Summary: On 15 February 2026 the Moonwell lending protocol activated governance proposal MIP-X43. One oracle configuration priced cbETH with the raw cbETH/ETH exchange rate instead of multiplying it by the ETH/USD price, so cbETH showed about $1.12 instead of about $2,200. Liquidators and borrowers used the wrong price and left the protocol with $1.78M of bad debt. The pull request behind MIP-X43 has commits co-authored by Claude Opus 4.6, which led some observers to call it possibly the first major exploit linked to "vibe-coded" Solidity (c); Moonwell itself did not blame AI.
- Numbers:
  - Bad debt $1,779,044.83 in total; 1,096.317 cbETH seized by liquidators; fixing the oracle needed a 5-day governance vote and timelock, so liquidations went on in the meantime (a).
  - Pull request 578 was merged on 2026-02-10 with 11 commits; 4 of them carry the trailer "Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>" (b).
  - My reading of the diff (b): commit 0898069b7e, which carries the Claude trailer, adds `_oracleConfigs[BASE_CHAIN_ID].push(OracleConfig("cbETHETH_ORACLE", "cbETH", "MOONWELL_cbETH"))` for Base. The same commit deletes the earlier, commented-out version of that line and a note that said "some oracles are commented out as they have composite oracles". A co-author trailer shows that an AI tool was used in the commit. It does not show who chose that line.
  - The post-mortem does not mention AI (a). The Block: "Moonwell has not attributed the incident specifically to AI-generated code" (c).
  - Auditor Pashov, who raised the AI link, called it a mistake "even a senior Solidity developer could have made". He later accepted that the team had unit and integration tests in a separate pull request and an audit from Halborn, and said the bug "could have been caught with an integration test" (d).
  - OECD lists it as an AI incident with "Economic/Property" harm, $1.78 million (e). DeFiLlama classes it as "Oracle Manipulation", technique "Oracle Misconfiguration", $1,780,000 (f).

### Nagli2026-Moltbook Hacking Moltbook: The AI Social Network Any Human Can Control
- Authors: Gal Nagli (Wiz); Year: 2026; Venue: grey literature (security vendor research blog)
- URL opened: https://www.wiz.io/blog/exposed-moltbook-database-reveals-millions-of-api-keys (blog post, 2 Feb 2026)
- Status: VERIFIED
- Tier: C
- Touches: none
- Summary: Wiz found that Moltbook, a social network for AI agents, used a Supabase database without Row Level Security, and the database key shipped in the site's JavaScript gave anyone full read and write access. The founder had said in public that he "didn't write a single line of code" for the site. Wiz calls keys left in front-end code "a recurring pattern we've observed in vibe-coded applications". The team fixed it within hours of disclosure.
- Numbers: 1.5 million API authentication tokens, 35,000 email addresses, and private messages between agents were exposed.

### Palmer2025-Lovable Statement on CVE-2025-48757
- Authors: Matt Palmer; Year: 2025; Venue: grey literature (researcher blog) and the CVE record
- URL opened:
  - (a) https://mattpalmer.io/posts/statement-on-CVE-2025-48757/ (statement with scan results)
  - (b) https://mattpalmer.io/posts/CVE-2025-48757/ (advisory, 29 May 2025)

- Status: VERIFIED
- Tier: C
- Touches: none
- Summary: Apps generated with the Lovable platform were deployed with missing or weak Row Level Security on their Supabase databases, so anyone could read or write their tables. The researchers found this on one Lovable site and then scanned the homepages of sites listed on Lovable's showcase.   - Exposed data included names, emails, phone numbers, API keys, payment details and Google Maps tokens (a, b).
  - CVSS 3.1 base score 9.3 (critical); affects Lovable through 2025-04-15; CVE published 2025-05-30 (c).

### GTSSLab2026-VibeSecurityRadar Vibe Security Radar
- Authors: Hanqing Zhao and colleagues, Systems Software & Security Lab, Georgia Tech; Year: 2025–2026 (live catalog); Venue: grey literature (research catalog, with news coverage)
- URL opened:
  - (a) https://vibesecradar.com/ (catalog homepage, read on 2026-10-21)
  - (b) https://github.com/HQ1995/vibe-security-radar (README, read with the GitHub API)
  - (c) https://infosecurity-magazine.com/news/ai-generated-code-vulnerabilities (news, 26 Mar 2026, Kevin Poireault)
- Status: VERIFIED
- Tier: B
- Touches: N1
- Summary: The catalog starts from published CVE and GitHub security advisories, finds the commit that fixed each one, and traces back to the change that introduced the flaw. A case counts only when an AI authorship signal (commit trailer, co-author line, agent transcript) is tied to the exact commit and code hunk that the security fix later closes (b). The authors say it is a lower bound and "not a rate comparison" between AI and human code (b). Claude dominates the cases partly because Claude Code "always leaves a signature", while inline suggestions from other tools leave no trace (c).
- Numbers:
  - 303 cases cataloged, from advisories dated May 2025 to September 2026 (cutoff 2026-09-26); 30,377 advisories in scope, but only 4% to 18% of each month's advisories were researched; peak month July 2026 with 65 cases; Claude appears in 241 of 303 cases; one project (openclaw/openclaw) holds 35 of 303 (a).
  - In March 2026 the catalog had 74 confirmed cases; 35 new CVEs disclosed in March 2026 alone, up from 6 in January and 15 in February; the founder estimated the true number at "five to 10 times" what they detect, "roughly 400 to 700 cases" (c).
  - I could not tell whether any case is a smart contract: the case list loads with JavaScript and the page HTML has no Solidity or DeFi terms.
- Delta: It shares one step with the project, tracing a fix back to the commit that introduced the flaw, and it ties the flaw to an AI-signed commit. It works backwards from advisories and only sees AI tools that sign their commits, so it gives a lower-bound count and no rate, and it has no human baseline on the same task. It uses no executable exploit and, as far as I could see, no smart contracts. The project runs a forward, controlled comparison: the same feature request, the same starting code and the same PoV for the human and for each agent, plus a control group.
