## Notes

- **62350.** List B's rank-1 candidate is the `removeFungible` index bug. That bug is finding 62348, which this function reaches through `useBalance = true`. It is not this finding, so I used candidate 2 for the verdict. List A's rank-1 candidate, about rounding, is also a different issue.
- **63008.** The fix is one line in `reset`. The harm shows up in other functions (`_zeroForOneCreditRewards` and `CompensationPriceFinder.getZeroForOne`), but the fix does not change them. The full "steal all rewards" attack also depends on a separate finding (H-02, `rewardGrowthOutsideX128` not set up). The fix-scope note says an earlier commit changed the upward iterator. That commit is not the cited fix.
- **64083: the key is outside the threat model.** The function is `onlyOwner`, and in the key's attack path the owner is the attacker. The owner hides the stake, deposits, and then adds the NFT back through `stakeNxm`. List B rejected the issue for exactly this reason. List A got around it by assuming the owner removes the NFT and an outside user back-runs the removal. The same fix commit also changes `_stakeNxm` and an oracle check. The fix-scope note says those changes belong to other findings.
- **64637.** The fix-scope confidence is medium. The fix is a squash commit that also changes `cancel` for other findings: it uses `safeTransfer` instead of try/catch, refunds the taker only if the taker deposited, sends leftover yield on, and sets the status before the transfers. List B's candidates 2, 3 and 4 line up with those other changes, not with this finding.
- **64661.** The finding text puts the root cause in `handleForwardData`, which never writes the start-time slot. But the fix changes only the `>` in `getRewardRateInside`. Both lists name both parts.
- **64662.** The fix comes from two commits that rewrite the whole `amountDelta` calculation. A refund now rounds down, and only the delta rate is used. The key's main impact is a pool freeze: the saved balance runs short and a later swap reverts with `SavedBalanceOverflow`. Theft only works with low-decimal tokens. List A's candidate gives the right mechanism but not the freeze.
- **64693: the key may be outside the threat model.** The finding does not describe an outside attacker. The recipient contract is chosen by the claiming user, so a recipient that reverts or returns a bad value mainly hurts that user's own integration. The fix commit is a squash of many audit changes. In the same statement it also passes `toSend` instead of `amount` to `onClaim`. That matches List B's rank-1 candidate, but it is not part of this finding's text.
- **65025.** The fix commit also adds a new `setBuilderAdmin` function. The fix-scope note treats it as an extra feature, not part of the fix. It does not change the verdicts.
- **65027.** The key also says the `realizedPremium != 0` check lets a burn skip the commission. The fix keeps that check and only adds the branch for zero short and long amounts. Both lists found the part that was fixed.
- **62348.** The fix touches only `removeFungible`. I have nothing else to note.
