- **Removing a staking NFT that still holds stake or rewards drops it from the vault's books, so an attacker can buy shares cheap and then bring the value back**
  - Root cause: lines 734-738 remove `tokenId` from `tokenIds` and run `delete tokenIdToPool[tokenId]` with no check that the NFT is empty. Nothing first calls `_withdrawFromPool(...)` for its stake and rewards. After this, `stakedNxm()` (lines 476-500) no longer counts the NFT, so `totalAssets()` and the share price fall at once. The vault also cannot recover the value itself: `getRewards()` only loops over `tokenIds`, and `unstakeNxm(tokenId, ...)` now calls `IStakingPool(address(0)).withdraw(...)`, which reverts.
  - Attack sketch: (1) The owner calls `removeTokenIdAtIndex(i)` on an NFT that still holds expired stake or unclaimed rewards. (2) The attacker back-runs it with `deposit()` or `mint()` at the lower share price. (3) The attacker calls the Nexus staking pool's `withdraw(tokenId, true, true, tranches)` directly for the removed NFT. In Nexus v2 that call is permissionless and pays the NFT owner, which is the vault. NXM lands in the vault, and `_updateBefore` wraps it on the next action. (4) `totalAssets()` jumps back up, and the attacker calls `redeem()`/`withdrawFinalize()` and takes a share of the restored value that belonged to the earlier holders. Even without step 3, holders with pending requests lose value, because `withdrawFinalize` prices shares at finalize time.
  - Severity: Medium
  - Confidence: medium (that the Nexus `withdraw` is permissionless comes from outside knowledge; the interface in context does not show it)

- **The missing `update` modifier means stake that returns later is charged admin fees as if it were rewards**
  - Root cause: `removeTokenIdAtIndex` has no `update` modifier (line 733). `lastStaked` and `lastBalance` are not refreshed, and the removed NFT's value is gone from `stakedNxm()`. When the removed NFT's principal later comes back as NXM or wNXM (step 3 above), `_updateBefore` sees `balance > lastBalance` and `lastStaked <= staked` (staked did not fall, because the NFT was already off the books). So it runs `adminFees += (balance - lastBalance) * adminPercent / DIVISOR` on principal, not on rewards.
  - Attack sketch: After the removal, any user calls the Nexus pool `withdraw` for the removed token and then calls any `update` function, for example `deposit` with 1 wei. With the default `adminPercent = 100`, 10% of the returned principal goes to `adminFees` and comes out of `totalAssets()`. Holders lose that amount for good.
  - Severity: Medium
  - Confidence: low-medium

- **Stake left on a removed NFT is locked forever, because the vault can never track or unstake it again**
  - Root cause: line 738 deletes `tokenIdToPool[tokenId]`, and no function can write it back for an existing token. `stakeNxm(_, _, tokenId)` looks up `tokenIdToPool[_requestTokenId]`, which is now `address(0)`, so it reverts. `unstakeNxm` and `extendDeposit` also resolve the pool to `address(0)`. `tokenIdToTranches[tokenId]` is not deleted either, so stale tranche data stays in storage.
  - Attack sketch: No attacker step is needed. Once the owner removes an NFT that still holds stake (for example, by passing a wrong index; swap-and-pop on line 735 moves the last element, so indexes shift between owner transactions), its NXM can only be reached through a direct permissionless Nexus withdraw, if one exists. Otherwise it is lost to stNXM holders.
  - Severity: Medium (an owner mistake, not an unprivileged exploit)
  - Confidence: low
