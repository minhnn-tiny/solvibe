- **1. Anyone can call `init` at any time, take over `builderAdmin`, and sweep all builder commission held by the wallet**
  - Root cause: `function init(address _builderAdmin) external { builderAdmin = _builderAdmin; }` (target.sol lines 2320 to 2322) has no access check. It does not require `msg.sender == FACTORY`, even though the wallet stores `FACTORY` as an immutable. It also has no "already initialized" guard, so it can be called again after `BuilderFactory.deployBuilder` has set the real admin. `sweep` (line 2324 onward) trusts `builderAdmin` alone.
  - Attack sketch: The factory owner deploys a builder wallet with `deployBuilder(code, admin)`. Users then open positions through `PanopticPool.dispatch(..., builderCode)`. On each mint, `CollateralTracker` moves `builderSplit` (25%) of the commission, as CollateralTracker shares, to the wallet address from `RiskEngine._computeBuilderWallet(builderCode)`. The wallet holds no positions, so `numberOfLegs(wallet) == 0` and its shares can be transferred freely. The attacker (any EOA) calls `BuilderWallet(wallet).init(attacker)`, then `sweep(collateralTracker0, attacker)` and `sweep(collateralTracker1, attacker)`. The attacker receives all accumulated shares and calls `redeem` on each CollateralTracker for the underlying tokens. The attacker can repeat this on every builder wallet. Builder wallet addresses are public, because they are deterministic CREATE2 addresses and are emitted in `CommissionPaid`. The attacker can also put both calls in one transaction, so the real admin has no chance to react.
  - Severity: High (direct theft of the builders' entitled commission, repeatable on every builder wallet).
  - Confidence: high.

- **2. Attacker can overwrite `builderAdmin` with an address nobody controls and lock the builder out of its fees**
  - Root cause: the same unrestricted, re-callable write `builderAdmin = _builderAdmin` at line 2321.
  - Attack sketch: The attacker calls `init(address(0xdead))` on a builder wallet. The legitimate admin's `sweep` now reverts with `NotBuilder`. The admin can call `init` again to take control back, because `init` is open to everyone. But the attacker can watch the mempool and front-run each recovery or sweep with another `init` call, so the builder never collects its share of commission. Neither the factory nor the owner has a function to fix the admin. This is a weaker form of candidate 1 with the same root cause. In practice an attacker would steal the funds rather than lock them.
  - Severity: Medium (loss of access to entitled fees through griefing).
  - Confidence: medium.
